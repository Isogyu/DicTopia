## 1. 本書の位置づけ

提供されたデザイン画像をもとに、ホーム画面のデザイン方針を**ダークテーマからライトテーマへ転換**し、あわせて以下の機能を追加・変更する。

| # | 項目 | 内容 |
|---|---|---|
| A | 週替わりお題機能 | 一時停止（フィーチャーフラグでOFF、自由な新語投稿のみ） |
| B | ホーム画面 | 画像デザインに合わせて全面刷新（ライトテーマ、検索バー、Heroセクション等） |
| C | コメント機能 | 新規実装 |
| D | ニックネーム・カテゴリタグ | 新規実装（`words`テーブルに列追加） |
| E | ログインボタン | 見た目のみ配置（機能は将来対応、クリックしても何も起こらないダミー） |
| F | 将来の認証機能に向けた下地 | `words`/`comments`に`user_id`（nullable）を先行して追加（今回は常にNULL） |

---

## 2. 要件A: 週替わりお題機能の一時停止

### 2.1 方針
コードを削除・コメントアウトするのではなく、**フィーチャーフラグ**で制御する。

- 環境変数 `NEXT_PUBLIC_FEATURE_WEEKLY_TOPIC`（`"true"` / `"false"`、今回は `"false"` に設定）を新設する。
- フラグが `false` の間:
  - ホーム画面のHeroセクションは、後述3章の新デザイン（お題非表示版）を表示する。
  - SubmissionModal（造語投稿フォーム）の `topic_id` は送信しない（常に `null` として投稿する）。
  - Navbarの「今週のお題」バッジは表示しない。
- `topics`テーブル・関連APIコードは削除しない（将来 `true` に戻すだけで復活できる状態を維持する）。

### 2.2 完了条件
- ホーム画面にお題関連のUIが一切表示されない。
- 新規投稿された造語の `topic_id` が全て `null` である。

## 3. 要件B: ホーム画面デザイン刷新

### 3.1 デザイン方針の転換
v1.0仕様書6章で定義した「Dark Slate基調」を、**提供画像に準拠したライトテーマ**（白基調、インディゴ系プライマリカラー）に変更する。既存のダークテーマ実装（Tailwind設定・コンポーネント配色）は本要件で洗い替える。

### 3.2 画面構成（上から順に）

| セクション | 内容 |
|---|---|
| Navbar | ロゴ「DicTopia」＋タグライン、新語検索バー（要件3.4）、「新語を追加する」プライマリボタン、「ログイン」ボタン（要件E、ダミー）、ハンバーガーメニュー（本スコープでは装飾のみ、クリックしても何も起こらない） |
| Hero | 見出し・説明文、CTAボタン2種（「新語を追加する」＝SubmissionModal起動、「使い方を見る」＝リンクのみ配置、遷移先ページの中身は本スコープ外）、装飾イラスト（静的画像アセットでよい。Devinは仮のプレースホルダー画像で実装してよい） |
| NewestWords | 新着造語を3カードのグリッドで表示。各カードに「NEW」バッジ（投稿24時間以内）、カテゴリタグ、投稿者ニックネーム、相対時間（「2時間前」等）、投票数、コメント数、リアクション合計数を表示 |
| PopularRanking | 投票数上位5件を順位付きリストで表示（1〜3位はメダルアイコン、4〜5位は数字） |
| RecentComments | 直近投稿されたコメントを時系列で表示（コメント本文の抜粋、対象の造語名、投稿時間） |
| BottomCTA | 「あなたの言葉が、未来の辞書に。」の訴求文＋「新語を追加する」ボタン |

### 3.3 既存コンポーネントとの関係
- v1.1で実装予定だった `HeroTopicCard`（お題表示版）は、要件Aによりこのタイミングでは使用しない。上記Heroセクションに置き換える。
- `Leaderboard`（v1.0設計のTop10）は `PopularRanking`（Top5、画像準拠のコンパクト表示）に置き換える。将来「もっと見る」導線でTop10以降を見せる拡張は本スコープ外とする。
- `NewestList` は `NewestWords`（カードグリッド形式への変更）として実装し直す。

### 3.4 検索機能
- Navbarの検索バーに入力すると、`word`または`definition`に部分一致する公開済み造語を検索する（大文字小文字を区別しない部分一致検索、全文検索エンジンの導入は本スコープ外）。
- 検索結果はドロップダウンで即時表示する（専用の検索結果ページは設けない）。

## 4. 要件C: コメント機能

### 4.1 要件
- 造語1件に対し、誰でも（匿名で）コメントを投稿できる。
- コメント本文は1〜200文字。
- 投稿時、造語投稿と同様にOpenAI Moderation APIによる事前検閲を行う（`flagged: true`の場合は投稿を拒否する）。
- コメントには要件Dのニックネームを任意で付与できる（未入力時は「名無し」と表示）。
- コメントの通報・削除機能は本スコープには含めない（将来拡張）。

### 4.2 表示箇所
- 造語個別ページ（`/word/[id]`）: 該当造語への全コメントを時系列で表示し、コメント投稿フォームを設置する。
- ホーム画面のRecentComments: 全造語を横断した直近コメントのフィード表示（3.2参照）。

---

## 5. 要件D: ニックネーム・カテゴリタグ

### 5.1 ニックネーム
- 造語投稿・コメント投稿の両方で、任意入力のニックネーム欄を追加する（1〜30文字、未入力可）。
- ログイン機能（要件E）が未実装のため、ニックネームはユーザーアカウントに紐づかない**自己申告制の表示名**である（同じニックネームを別人が名乗ることを防ぐ仕組みは持たない）。
- 未入力の場合、UI上は「名無し」と表示する。

### 5.2 カテゴリタグ
- 造語投稿時、以下の固定カテゴリから**1つを必須選択**する。

```
ライフスタイル / 感情・感性 / 仕事・ビジネス / ネット・SNS / 恋愛・人間関係 / その他
```

- 既存の`ai_context_tags`（AI自動生成タグ、3〜5個）とは別概念として併存させる。カテゴリはユーザー選択・表示用、`ai_context_tags`はSEO用の裏方データという役割分担とする。

---

## 6. 要件E: ログインボタン（ダミー）

- Navbarに「ログイン」ボタンを画像通りに配置する。
- クリック時の挙動は**何も起こらない、または「近日公開」を示すトースト通知を出す**のみとし、認証処理・ユーザーテーブルは一切実装しない。
- 将来、認証機能を実装する際の受け皿として、ボタンの配置場所とデザインのみ確定させる。

---

## 7. 要件F: 将来の認証機能に向けた下地

### 7.1 背景
現時点ではログイン機能を実装しない（要件E）が、将来実装する際に「匿名投稿済みのデータをアカウントに紐づけられない」問題を避けるため、今のうちに受け皿となる列だけを追加しておく。

### 7.2 要件
- `words`テーブル・`comments`テーブルの両方に、`user_id`（nullable、Supabase Authのユーザーと将来紐づけるためのUUID列）を追加する。
- 今回のリリースでは認証機能自体が存在しないため、新規投稿・新規コメントの`user_id`は**常にNULL**として保存される。
- UI・APIともに`user_id`を意識した実装（ログインユーザーの投稿一覧表示等）は本スコープに含めない。列を用意するだけに留める。

## 8. スコープ外・見送り事項

- ユーザー認証・アカウント機能そのもの（要件E参照、ボタンのみ）
- コメントへの返信（スレッド化）、コメントの通報・削除
- ハンバーガーメニューの中身（設定・ヘルプ等のページ）
- 「使い方を見る」リンク先ページの中身
- 検索の全文検索対応（形態素解析・あいまい検索等）
- ニックネームの重複防止・なりすまし対策

- [ ] 検索バーに入力すると該当する造語が絞り込まれる
- [ ] 「ログイン」ボタンをクリックしても認証処理は一切走らない
